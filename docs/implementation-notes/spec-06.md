# Spec 06 implementation notes

Deliberate choices made while implementing Spec 06 (Web Board UI). Reviewers: treat these as decided unless one contradicts the spec or an ADR.

## 06-01 App shell

- **Better Auth client scope.** The web app uses Better Auth's client (`createAuthClient` from `better-auth/react`, no plugins) for sign-in, sign-up, sign-out, social sign-in, and `getSession`. It does not use the organization client plugin: `/api/auth/organization/*` stays blocked (see `docs/better-auth.md`). Every Company, member, Role, and Invite action goes through the Hono RPC client (`hc`) on our own routes. Decided with the user; ticket 06-02's "Use the Better Auth organization client" wording is superseded.
- **Typed API client.** `AppType` is exported from `apps/server/src/app.ts`. `apps/web` has `@clankerboard/server` as a devDependency and imports it as `import type` only, so no server code reaches the bundle. `unwrap()` in `apps/web/src/lib/api.ts` turns a non-2xx answer into an `ApiError` carrying the server's plain message (our routes send `{ error }`, Better Auth sends `{ message }`) and types the success body by dropping the error-status members of the union.
- **Routing.** TanStack Router with file-based routes (`apps/web/src/routes`) and the Vite plugin. `routeTree.gen.ts` is committed, because `pnpm typecheck` runs before any build in CI, and Biome ignores it. Fixed routes are `/`, `/sign-in`, `/sign-up`, `/invite` (token stays in the URL fragment), then `/$companySlug/...`. Later cards add routes under `$companySlug`.
- **Reserved Company slugs.** `api`, `invite`, `sign-in`, `sign-up`, `mcp`, `healthz` are rejected as explicit slugs (400 "That slug is reserved.", on create and rename) and skipped when a slug is derived from a name (so "API" becomes `api-<hex>`). The list is `reservedCompanySlugs` in `packages/shared/src/companies.ts`: add a slug there whenever a new fixed top-level route is added.
- **The active Company comes from the session, not the URL.** Entering any `/$companySlug` route runs `activateCompany` in `beforeLoad`: it fetches `/api/companies` fresh, 404s the route (`notFound`) if the slug is not one of the User's Companies, and calls `PUT /api/active-company` when the session's active Company differs. Company-scoped queries then run against the right Company. When the slug changes, every query that is not session-wide (`session`, `companies`, `auth-providers`) is removed, so a board never shows another Company's cache. Later cards should therefore start their Company-scoped query keys with their own name (not `session` or `companies`).
- **Known limit: two tabs on two Companies.** The cookie is shared, so the last tab to switch wins for every tab's API calls, and the server ends other-Company streams on a switch (Spec 05). The app does not paper over this (a re-assert on focus would only flip the other tab's stream back). 06-08 should handle a stream that reconnects onto a different Company than its page shows.
- **Where `/` lands.** The session's active Company, else the browser's last Company (localStorage `clankerboard-last-company`), else the first in the list. A new sign-in is a new session with no active Company, so the remembered slug is what makes "land on my last active Company" work across sign-outs. With no Company the page asks for one, with the account menu available so a stuck User can sign out.
- **Expired session.** One handler (`onUnauthorized` in `api.ts`, wired in `router.tsx`) runs on any 401 from the `hc` client: it clears the query cache and goes to `/sign-in?redirect=<current path, search, and hash>`. Route guards (`requireSession`) do the same for a signed-out visit. The session itself is read once and cached (`getSession`, `staleTime: Infinity`), so a cookie that expires mid-visit is noticed by the next API call, not polled. Sign-in and sign-up send the person to `redirect` afterwards. `redirect` must be a path on this site (`/x`, never `//x` or a backslash), otherwise it is ignored.
- **Permission matrix moved to `packages/shared`.** The pure Role functions (`canChangeRole`, `canRemoveMember`, `canInvite`, `canInviteToTeam`, `canListInvites`, `canManageTeams`, `canManageTeamMembers`, `canSetTeamRole`, `canSeeAllAgents`, `canRevokeAgent`, `canUpdateCompany`, `canListMembers`) now live in `packages/shared/src/permissions.ts` so the UI hides controls with the same functions the server enforces. `packages/domain/src/permissions.ts` re-exports them, so server imports and the "one function per permission question" rule are unchanged. Checks that need a request or a Project (`canSeeProject`, `assertMay*`) stay in domain. The web app never imports `@clankerboard/domain`.
- **Theme.** Tailwind v4 with the shadcn variables in `apps/web/src/app.css`, dark mode as a `dark` class on `<html>`. Storage key `clankerboard-theme` holds `light` or `dark`; absent means "follow the system" (so a System choice removes the key). An inline script in `index.html` applies it before first paint, and `lib/theme.ts` keeps it live (including a live system change while on System). The key is recorded in `.claude/skills/redesign/SKILL.md`. The stock shadcn dark values were replaced by hand-tuned ones (a visibly lighter card and popover, opaque borders, distinct secondary, muted, and accent), as the redesign skill warns.
- **Theme control copy.** The control is labelled "Appearance" (Light, Dark, System): "theme" is not an _Avoid_ term, but "Toggle theme" and similar fail the copy check, and "Appearance" is a single word.
- **Copy check skips Tailwind class lists.** `scripts/check-copy.mjs` no longer scans strings made only of lowercase utility words that carry a Tailwind marker (`-`, `:`, `[`, `/`) or are bare utilities from a short list (`flex`, `group`, ...). Otherwise `items-center` (item), `bg-card` (Card), `data-[state=open]` (state) and `group` (Group) fail in every component. Real copy still gets checked: it starts with a capital or contains plain English words. Chosen over allowlist entries, which would be a growing list of non-prose. The shadcn `"use client"` directives were deleted from the generated components (Vite does not need them, and "client" is an _Avoid_ term).
- **shadcn setup.** Components are generated into `apps/web/src/components/ui` with the shadcn CLI (`components.json`, `new-york` style, neutral base) and then formatted by Biome. The `@/` alias maps to `apps/web/src` in both `tsconfig.json` and `vite.config.ts`. Biome's CSS parser has `tailwindDirectives` on, since `@theme` and `@apply` fail otherwise.
- **Touch targets.** Header controls (Company switcher, Appearance, Account, the logo link) are 44px (`size-11`/`h-11`) below the `md` breakpoint and shrink to the shadcn defaults above it. The auth forms use 44px inputs and buttons at every width, with a 16px font on phones so iOS does not zoom on focus.
- **Mobile header.** The wordmark collapses to the icon below `md` so the Company switcher gets the room; a long Company name truncates. The switcher is a dropdown of Companies plus a "Create company" dialog.
- **The Company home is a stub.** `/$companySlug` shows the Company name and the viewer's Role. 06-05 replaces it with the Projects list. The Role comes from the route context set in `beforeLoad` (`/api/companies` carries it), not an extra request.
- **Invite page ported, not redesigned.** `/invite` keeps the old flow (lookup, sign-up or sign-in inline, accept) on the new components. 06-02 owns its redesign (Team, Role, bad-link messages). Creating an Invite is not in the UI until 06-02 (the old Company home form is gone), so `e2e/invite.spec.ts` creates the Invite over HTTP with the owner's session and only drives the invitee's browser.
- **Sign-up screen cannot say whether sign-up is open.** No endpoint exposes `OPEN_SIGNUP`; the screen shows the server's own refusal ("Sign-up needs an invite."). Left as is: only a public config endpoint would change that, and 06-04 adds one for the server URL.
- **Playwright setup.** Port and database name are no longer fixed: `e2e/config.mjs` derives them from the checkout path (`E2E_PORT` and `E2E_DB` override), so two worktrees can run the suite at once against the shared test Postgres. Every spec runs in two projects: `desktop-light` (1280x800, light) and `mobile-dark` (375x812, touch, dark). Specs that test the theme set their own `colorScheme`. A spec that depends on the viewport reads `page.viewportSize()`.
- **OAuth in tests.** The e2e server has no OAuth credentials, so the provider buttons are covered by stubbing `/api/auth-providers` and `/api/auth/sign-in/social` in the browser. This proves the screen's logic (only enabled providers, the right provider and return path are sent), not the redirect to GitHub or Google.
- **Dev server origin (unverified).** Under `vite dev` the browser's Origin is `http://localhost:5173` while Better Auth trusts `BASE_URL` (default `http://localhost:3000`). If Better Auth rejects sign-in POSTs there, run the server with `BASE_URL=http://localhost:5173`. The built app (what Playwright tests) is same-origin and unaffected.

## 06-04 Agents and API Keys UI

- **Public config endpoint.** `GET /api/config` (no session) answers `{ publicUrl, signUpOpen }`. `publicUrl` is `BASE_URL`. `signUpOpen` is true when open sign-up is on or the instance has no User yet (the same rule `isSignUpAllowed` applies before it looks at an Invite), so it comes from one domain function, `isSignUpOpen`, which `isSignUpAllowed` now calls. Nothing else is exposed (a test pins the keys). It is tested over the HTTP seam in `apps/server/test/public-config.test.ts`.
- **The sign-up screen uses it (supersedes the 06-01 note).** When `signUpOpen` is false the screen shows "Sign-up needs an invite. Ask for an invite link." and no form or OAuth buttons (OAuth sign-up is refused by the same rule). The invite page is unaffected, since an Invite is what lets someone in. If the config call fails the form is shown and the server's own refusal appears on submit. The config is fetched fresh on every visit, because sign-up closes after the first User.
- **Setup snippets.** The URL is `publicUrl` with trailing slashes removed, plus `/mcp`. The command is `claude mcp add --transport http clankerboard <url>/mcp --header "Authorization: Bearer <key>"` with the real key, so it is paste-ready. The `.mcp.json` references `${CLANKERBOARD_API_KEY}` and never holds the key, with a separate `export` line carrying it. The server name is the fixed `clankerboard`. Snippet syntax is from Claude Code's MCP docs and was not run against a Claude Code install.
- **The key is never re-fetched.** It exists only in the create-key dialog's state: it is not put in the query cache, and closing the dialog or the X discards it. The key list is `GET /api/agents/:id/keys`, which never returns it. A test checks the page text after closing and after a reload.
- **Which controls show.** They mirror the server rules with the shared functions: rename and "Create key" for the Agent's owner only (an admin gets 403 for both), revoke for the owner of the Agent or an owner or admin (`canRevokeAgent`), nothing at all on a revoked Agent. A plain member's list is already only their own, since the server filters it; owners and admins get every Agent, their own first.
- **Revoked marking.** A revoked Agent keeps its place with a "Revoked" badge, a struck-through name, a dimmed card, and no actions; a revoked key gets the same badge and strike-through. Revoking an Agent or a key asks first, since it cannot be undone.
- **Keys per Agent.** Keys load per Agent (the API has no list for all). They show open for the viewer's own live Agents and collapsed otherwise, so an admin's page does not fire a request per Agent in the Company.
- **Navigation.** The Agents page is `/$companySlug/agents`, reached from an "Agents" item in the account menu (shown on Company pages only). There is no primary nav yet; whichever card adds one can move the link.
- **Last used.** Shown as a relative time ("Used 5 minutes ago", "Never used"), with the exact time in the tooltip. The key prefix (`cb_` and 8 characters) is shown followed by `...`, without a label word, since "prefix" is an _Avoid_ term for Project Key.
- **Layout.** Each Agent is a card, not a table, so it works at 375px. The cards sit in a grid whose column is `minmax(0, 1fr)`, otherwise a long email or name widens the page. Touch targets are 44px below `md`. Long Agent names wrap; a long owner email truncates.
